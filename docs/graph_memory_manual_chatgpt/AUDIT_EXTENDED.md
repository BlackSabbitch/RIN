# Audit: graph_memory_manual_chatgpt_extended

Дата аудита: 11 августа 2026 года.

## Что проверялось

1. Сохранён ли базовый roadmap, то есть не потеряны ли ключевые технические решения
   исходного мануала и базового учебного дубля.
2. Не превратились ли расширения в тихую подмену исходной архитектуры.
3. Нет ли в подключённом корпусе текста стилистических хвостов, которые были
   специально запрещены:
   сравнения с DTI-проектом и обращение к читателю во втором лице.
4. Собирается ли проект чисто в LaTeX-смысле:
   без неопределённых ссылок и без дублирующихся меток.

## Итог по roadmap

Базовый roadmap сохранён.

В расширенной версии по-прежнему присутствуют:

- граф как основной адресуемый субстрат памяти;
- различение event-log, памяти, телеметрии и управляющего состояния;
- typed nodes / typed edges / provenance / confidence / activation / timescales;
- retrieval как двухшаговый процесс: якоря + локальное разворачивание;
- единый обходчик с разными политиками для retrieval / внутренней жизни / сна;
- fusion как генератор кандидатов, а не тихий коммит фактов;
- пропагация уверенности, ревизия и TMS-подобная логика;
- Stage 1 как минимальный наблюдаемый срез, а не псевдо-готовая «полная Рин»;
- дальние ветви (гиперграфы, динамическая память и др.) как исследовательские, а не
  как немедленная замена явного графа.

Потерь по этому перечню в ходе расширения не обнаружено.

## Что добавлено сверх базового дубля

Новые технические добавки внесены открыто, а не как замена исходнику.

1. Retrieval-аудит как кортеж диагностик:
   `anchor recall`, `bridge rate`, `contradiction hit rate`, `provenance coverage`.

2. Более явная математика retrieval:
   переходный оператор, роль температуры, hitting time, проводимость, связь локального
   шага с глобальным поведением потока.

3. Каналы свидетельств как внутренняя логика для одномерного поля уверенности:
   observation / report / inference / self-model / social echo, с разной надёжностью
   и штрафом за зависимость источников.

4. Dual budget context packer:
   раздельный бюджет на evidence-узлы и на glue-материал.

5. Явный каталог failure modes:
   hub collapse, bottleneck starvation, premature certainty, provenance erosion,
   mood lock-in, context bloat, pending avalanche.

6. Чистое правило для дальних ветвей:
   резервуарный, аттракторный или квантовый слой может предлагать / модулировать /
   давать признаки, но не должен напрямую захватывать write-path явной памяти.

## Где расширение спорит не с фактами roadmap, а с его неявной формой

Расширение нигде не заменяет молча базовые решения на противоположные. Но несколько
мест сделаны более жёсткими по форме:

- Разделение budgets в context packer выделено как самостоятельное инженерное решение,
  хотя в базовом тексте оно было лишь частично имплицитно.
- Внутренняя логика confidence расписана глубже, чем в roadmap, но внешний интерфейс
  всё равно оставлен одномерным, чтобы не взорвать Stage 1.
- Дальние ветви жёстче привязаны к правилу «только за чистым интерфейсом», чтобы
  не растворить адресуемую память в красивой динамике.

Это расширения и уточнения, а не отмена исходной архитектуры.

## Стилистический аудит

Для корпуса, который подключён в `extended`, выполнена отдельная зачистка:

- удалены сравнения с DTI там, где они выступали не как библиографический след, а
  как внешний проектный мост;
- удалены прямые обращения к читателю во втором лице;
- заменены несколько формулировок, где текст незаметно съезжал из учебного стиля в
  разговорно-адресный.
